A loop, not a pipeline.

The camera is the input. The object graph is the product. The verifier is the moat.

01

See

SAM 3.1 detects and tracks parts from text prompts. When the camera can't, tap the part instead.

02

Remember

Every part is a node in an append-only, hash-chained log. Restart the app and nothing is lost.

03

Reason

A model explains and plans, but only among steps the task graph allows. It can't touch the graph.

04

Verify

A safety kernel and five checks (count, order, safety, closure, function) gate the passport.

Three moments that matter.

Each one is a thing a chatbot cannot fake, shown in the replay.

THE DROP

It noticed before you did.

A screw leaves the bench and never reaches a tray well. The counter changes and the banner names the part and the time.

Simulated: flagged about 3 seconds after it leaves the frame.
THE DANGEROUS STEP

Stop. Disconnect the battery.

A hand goes for the SSD with the battery connected. The step card turns red. The model can explain the rule; it cannot override it.

Four hard-coded rules: ESD, power-off, hazard halt, no prying near a live cell.
THE RETURN

Lunch didn't make it forget.

Thirty minutes later a fresh process opens the same log. Same counts, same exceptions, same next step. Click any event to see that frame.

State is rebuilt from the event log alone.
THE ARTIFACT

What you keep.

A one-page passport and the JSON behind it. Counts that reconcile, every exception and how it was resolved, evidence frames, and a hash chain anyone can check.
